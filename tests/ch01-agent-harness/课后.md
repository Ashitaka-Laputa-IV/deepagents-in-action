# 【第 1 章：从 Agent Framework 到 Agent Harness】课后练习

## 课后练习

题目跨知识点、设情境、做对比，考查"能否运用/迁移"。

### 单选题

1. 某团队需要最大灵活性、精细控制底层执行引擎，选择直接使用 LangGraph 构建长期运行的 Agent，此时他们工作在哪一层？A
   - A. Runtime（底层）
   - B. Framework（中间层）
   - C. Harness（上层）
   - D. 无法确定

   > 批阅：✓ 解析：需要最大灵活性、精细控制底层→直接使用 LangGraph（Runtime 层）。

2. 某企业级项目要求模型无关、可随时切换厂商，且需要跨会话持久化记忆，最适合的选择是？B
   - A. LangGraph
   - B. Deep Agents
   - C. Claude Agent SDK
   - D. Codex SDK

   > 批阅：✓ 解析：模型无关 + 跨会话长期记忆，正是 Deep Agents 的独有优势。

3. 某团队全面使用 Claude 模型，需要与 Claude 深度集成并拦截、控制 Agent 行为，应优先选择？C
   - A. Deep Agents
   - B. Codex SDK
   - C. Claude Agent SDK
   - D. LangChain

   > 批阅：✓ 解析：全面 Claude + Hooks 系统拦截控制→Claude Agent SDK。

4. 某场景需要 OS 级别的沙箱模式（`read-only`、`workspace-write`、`danger-full-access`）以及内置 MCP Server 模式，应选择？A
   - A. Deep Agents
   - B. Claude Agent SDK
   - C. Codex SDK
   - D. LangGraph

   > 批阅：✗ 正确答案应为 C（Codex SDK）。解析：`OS 级别的沙箱模式` 和 `内置 MCP Server 模式` 是 **Codex SDK 的独有优势**（文中"Codex SDK 的独有优势：OS 级别的沙箱模式、内置 MCP Server 模式、云端执行环境"）。注意区分：Deep Agents 的对应特性是 **Sandbox-as-Tool**（本地运行、把特定操作发到远程沙箱），与 Codex 的"OS 级沙箱 + 内置 MCP Server"不是一回事。

5. 某 Agent 希望在本地运行，但把代码执行这类特定操作发送到远程沙箱中执行，这对应 Deep Agents 的哪个独有特性？B
   - A. 长期记忆
   - B. Sandbox-as-Tool 模式
   - C. 虚拟文件系统
   - D. 流式输出

   > 批阅：✓ 解析：本地运行 + 把特定操作发到远程沙箱 = Deep Agents 的 Sandbox-as-Tool 模式。

6. 一个 Agent 处理一个含 20 个文件、共 50000 tokens 的仓库，且只有部分文件当前步骤需要。按 Context Engineering 理念，正确处理方式是？B
   - A. 把 20 个文件完整内容一次性塞进 prompt
   - B. 用 `read_file` 按需读取，大文件用 `offset`/`limit` 只读需要的部分
   - C. 压缩全部文件后一次性塞入
   - D. 完全不读取文件，靠 LLM 记忆

   > 批阅：✓ 解析：Context Engineering 主张按需读取、只保留当前步骤所需信息。

### 多选题

1. 以下哪些场景适合选择 Deep Agents？（多选）ABC
   - A. 需要模型灵活性，不锁定任何厂商
   - B. 需要跨会话、跨线程的长期记忆
   - C. 需要完整的生产部署和可观测性方案（搭配 LangSmith）
   - D. 只需要快速写一个简单的单步问答

   > 批阅：✓ 解析：A/B/C 均为 Deep Agents 擅长场景；D 单步简单问答无需 Harness 的复杂能力。

2. 要构建复杂多步骤、自主性较高的 Agent，可选择在哪些层次工作？（多选）D
   - A. 直接用 LangGraph（Runtime）
   - B. 用 LangChain（Framework）
   - C. 用 Deep Agents（Harness）
   - D. 以上均可，取决于需求

   > 批阅：✓ 解析：三层均可用于构建复杂 Agent，取决于对灵活性/上手速度/开箱即用的需求。

3. Deep Agents 相对 Claude Agent SDK 和 Codex SDK，在架构层面的差异体现在？（多选）ACD
   - A. 模型无关
   - B. 支持长期记忆（Memory Store）
   - C. 虚拟文件系统 + 可插拔后端
   - D. Sandbox-as-Tool 模式

   > 批阅：✗ 正确答案应为 ABCD。解析：B（长期记忆 / Memory Store）也是 Deep Agents 的独有优势——文中明确"Claude Agent SDK 和 Codex SDK 都不支持这一特性"，因此它同样是相对竞品的架构差异。你漏选了 B。

4. 关于虚拟文件系统的可插拔后端，下列哪些说法正确？（多选）ABD
   - A. 后端可以是内存、磁盘、数据库或沙箱
   - B. 可以混合使用，不同路径路由到不同后端
   - C. 后端一旦选定不可更改
   - D. 这是 Deep Agents 独有的设计

   > 批阅：✓ 解析：A/B 正确；D 正确（可插拔后端是 Deep Agents 独有）；C 错误（可插拔意味着可更换/混合），你没选 C，正确。

### 判断题

1. Claude Agent SDK 支持跨会话、跨线程的长期记忆。Y
   > 批阅：✗ 正确答案应为 N。解析：文中明确"Claude Agent SDK 和 Codex SDK 都不支持这一特性（长期记忆）"，该陈述为假。
2. Deep Agents 采用 Sandbox-as-Tool 模式，Agent 在本地运行但可把特定操作发送到远程沙箱。Y
   > 批阅：✓ 解析：判断正确——这是 Deep Agents 独有特性。
3. 把文件信息全部塞进 prompt 可以彻底解决上下文溢出问题。N
   > 批阅：✓ 解析：判断正确——这正是传统做法的致命问题，会加剧溢出。
4. Deep Agents 的长期记忆能力是 Claude Agent SDK 和 Codex SDK 都不支持的。N
   > 批阅：✗ 正确答案应为 Y。解析：该陈述为真——Claude Agent SDK 和 Codex SDK 都不支持长期记忆（Memory Store），这是 Deep Agents 的独有优势。

### 案例分析题

1. 某公司要构建一个企业级 AI 编程助手，需求如下：
   - 不锁定任何模型厂商，希望能灵活切换
   - 需要跨会话记住用户的偏好
   - 需要安全地在远程沙箱中执行代码，同时 Agent 本身在本地运行
   - 需要完整的生产部署与可观测性方案
   请判断应选择哪个 Harness，并说明各项需求分别对应其哪些能力。
   Deep Agents:
   1. 使用`langchain`的模型抽象(`init_chat_model`)
   2. 使用`LangGraph State Store`
   3. 使用`Sandbox as Tool`
   4. 使用`LangSmith`

   > 批阅：✓（方向正确，1 处需纠正）。解析：选 Deep Agents 正确，四项能力对应基本成立。注意纠正：跨会话记忆应对应 **LangGraph Memory Store**（不是 State Store）。其余对应合理：① 模型抽象→模型灵活性/无关性；③ Sandbox-as-Tool→本地运行+远程沙箱执行；④ LangSmith→可观测性 + LangGraph Platform 生产部署。

2. 结合三层架构（Runtime / Framework / Harness），为"需要精细控制、长期运行、且需要快速开发上手"的团队，设计一个合理的分层选型策略并说明理由。
   使用`LangGraph`绘制底层运行图逻辑架构, 使用`langchain`作为主体框架, 使用`deepagents`快速开发

   > 批阅：✓（方向正确）。解析：你的分层与理由基本对应三层架构——LangGraph 作 Runtime（精细控制、长期运行的底层执行）、LangChain 作 Framework（标准化主体框架）、Deep Agents 作 Harness（快速开发开箱即用）。可进一步点明：对"精细控制、长期运行"需求用 LangGraph 掌握底层；对"快速开发上手"需求用 LangChain/Deep Agents 减少重复造轮子。整体已达标。
